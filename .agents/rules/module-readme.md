## 1. 任务前置：代码分析规程 (Pre-writing Analysis)

在落笔之前，**必须**完成以下分析，禁止凭假设或文件名推断写作。

- **目录全量扫描**：列举目标模块下的所有文件（含子目录），识别并排除测试目录（`__test__/`）——测试文件不参与逻辑分析，仅登记其存在。
- **源文件逐一阅读**：对每个非测试源文件提取以下四个维度：对外接口（导出的函数、类、常量及其签名）、核心依赖（区分内部模块与外部库）、控制流骨架（主路径、条件分支、异常处理策略）、隐含约定（注释中透露的约束、TODO、已知限制）。
- **调用关系溯源**：检索代码库中调用本模块导出接口的上游调用点，记录存在实质依赖关系的兄弟模块，以备交叉引用。
- **以代码为准**：若文件的实际行为与文件名语义存在偏差，须以**代码实际行为**为准，不得以文件名推断功能。

## 2. 文档结构规范 (Document Structure)

每份 README 必须严格遵循以下五段式结构，**不得增减章节、不得调换顺序**：

```
# src/<模块名> — <功能定位标题>
> 项目总览与相关模块的交叉引用（blockquote 块）
## 简介
## 目录结构
## 实现逻辑 [分析]
## 新增 / 重构 / 删除向导
```

**文档头部（H1 + Blockquote）**
- H1 格式：`# src/<模块名> — <功能定位标题>`，功能定位标题须为名词短语，精确描述模块的系统级职责，而非复述模块名。
  - ✅ `src/server — 后端服务端与直连会话模块`
  - ❌ `src/voice — voice 模块`
- Blockquote 格式：首行为项目总览链接（`参见 [README.md](../../README.md)`），次行为相关模块链接，须附一句话说明关联原因；若无直接关联模块，次行可省略。
- 相关模块仅列出与本模块存在实质调用或依赖关系的模块，禁止泛化列举。

## 3. 各章节写作要求 (Section Requirements)

**简介（`## 简介`）**

用 1~3 句话完成以下三点，缺一不可：
1. **模块职责**：本模块在系统中做什么（动词驱动，而非描述文件列表）。
2. **核心机制**：实现上述职责依赖的关键技术手段或架构模式。
3. **系统定位**：本模块服务于哪个上层模块或基础设施层。

禁止在简介中列举文件名或函数名。

**目录结构（`## 目录结构`）**

使用 ` ```text ` 代码块呈现树形结构，每个条目后**必须有注释**，注释描述该文件的唯一责任，而非复述文件名：
- ✅ `# 进程级互斥锁，保障多实例下端口与状态的安全抢占`
- ❌ `# 锁文件`

子目录仅展开一层；文件众多时以 `└── ...` 折叠并在注释中说明整体职责。

**实现逻辑（`## 实现逻辑` 或 `## 实现逻辑分析`）**

须严格基于源码阅读结果。子章节粒度规则：
- 源文件数量 **≤ 3**：按设计维度组织子章节（如"权限检测"、"状态分离"）。
- 源文件数量 **> 3**：按编号子章节（`### 1. 标题`、`### 2. 标题`）组织，每节对应一个核心机制。

每个子章节须包含：入口锚点（指出主文件或主函数，用反引号标记）、机制描述（做了什么 → 为什么这样做）、关键技术术语（括号内附英文原词）、关键约束或安全边界。

**新增 / 重构 / 删除向导（`## 新增 / 重构 / 删除向导`）**

必须提供三个子节，子节标题固定为：

```markdown
### 新增
### 重构
### 删除
```

- **`### 新增`**：列出添加新功能/维度时需要同步执行的操作，须覆盖入口注册和测试补充要求。
- **`### 重构`**：列出向后兼容性约束；若本模块含安全失败（Fail-safe）或故障敞口（Fail-open）策略，必须在本节显式声明并说明安全意图。
- **`### 删除`**：列出下线条件、清理步骤，并明确要求追溯并屏蔽所有上游调用方入口。

## 4. 语言风格准则 (Language Style)

- **语言**：全文中文；技术术语首次出现时括号内附英文原词，如"竞态条件（Race Condition）"。
- **句式**：陈述句为主；新增 / 重构 / 删除向导章节全部使用祈使句。
- **称谓**：以"本模块"指代文档所属模块，禁止使用"这里"、"此处"。
- **禁止**复述文件名或函数名代替逻辑描述。
- **禁止**使用"等"、"一些"、"若干"等模糊量词。
- **禁止**使用"显然"、"很简单"等主观评价词。
- **禁止**在正文中使用 Emoji 或非技术类修辞。

## 5. 质量自检清单 (Quality Checklist)

提交 README 前，须逐项确认，**所有项均须通过**：

**结构完整性**
- [ ] H1 使用"模块路径 — 功能定位标题"格式
- [ ] Blockquote 包含项目总览链接，相关模块链接已验证路径可达
- [ ] 五个章节均存在，无缺失、无顺序错乱

**内容准确性**
- [ ] 简介描述的模块职责与源码导出接口的实际用途一致
- [ ] 目录结构与 `list_dir` 扫描结果完全匹配，无遗漏文件
- [ ] 实现逻辑中提到的文件名、函数名、类名均在源码中实际存在
- [ ] 交叉引用的相关模块链接路径均已验证可达

**语言规范性**
- [ ] 新增 / 重构 / 删除向导各子节全部使用祈使句
- [ ] 技术术语首次出现时括号内附英文原词
- [ ] 全文无"等"、"一些"、"若干"等模糊量词

**安全与约束声明**
- [ ] 若模块含权限检查或安全失败策略，已在实现逻辑或「重构」节中显式说明
- [ ] 「删除」节已包含调用方追溯的明确要求
