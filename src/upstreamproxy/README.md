# src/upstreamproxy — CCR 上游代理网关模块

> 项目总览：参见 [README.md](../../README.md)

## 简介

本模块是运行于 CCR（Claude Container Runtime）端的上游代理通信网关。通过在本地启动微型中继并在环境变量层注入拦截策略，它允许大模型执行的子进程透明地穿越组织级内网限制，是连接云端执行沙盒与外部互联网的关键网络基础设施。

## 目录结构

```text
upstreamproxy/
├── relay.ts          # 代理服务器逻辑，负责建立 HTTP CONNECT 隧道和请求升级
└── upstreamproxy.ts  # 环境与鉴权管控，负责向进程暴露配置、隐藏连接凭证及合并证书
```

## 实现逻辑

### 1. 代理初始化与环境隔离 (`upstreamproxy.ts`)
- **注入与提取**：下载云端配发的根证书与本地 CA 实施合并注入，向衍生子进程暴露 `HTTPS_PROXY` 及免代理清单等规范变量。
- **内存探查防御**：通过 FFI 绑定底层调用隐藏进程核心状态，拦截利用诊断工具抓取进程内存连接凭证的安全攻击。

### 2. 隧道通信与二进制截获 (`relay.ts`)
为了穿越防火墙拦截，系统采用特定格式的连接。
- **协议升级包装**：伪装为本地 HTTP 代理服务拦截流量，随后打包附带 JWT 的鉴权头部，向目标网关进行升级握手。
- **Protobuf 轻量编码**：通过人工手写结构体前缀包裹数据块，规避了体积庞大的编译时解析依赖并显著提速。

### 3. 白名单与死循环规避
在环境变量注入阶段，主动过滤所有打往核心域名、元数据端点以及本地回环地址的流量，防止代理环路或在底层客户端工具中引起验证混乱。

## 新增 / 重构 / 删除向导

### 新增
- 新增基础服务例外请求地址时，在变量层硬编码的白名单清单内添加匹配规则。
- 扩充新的握手协议时补充对应环境适配策略。

### 重构
- 涉及网络拦截的链路必须保障安全失败（Fail-open）属性，异常时仅降级为直连，严禁向外抛出致命错误使容器挂起。
- 对于本地监听端口及二进制包块分段逻辑的变更，需同时满足主流 JS 运行时引擎的底层 API 兼容性要求。

### 删除
- 下线相关功能前，清除全部关于隐蔽进程状态设定的系统底层调用。
- 清洗进程运行环境内残存的证书与代理指向变量。
