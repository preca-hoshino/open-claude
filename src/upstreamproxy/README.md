# src/upstreamproxy — CCR 上游代理网关模块

> 参见 [README.md](../../README.md)
> 本模块由外层环境初始化入口调用，并负责为系统内衍生的所有底层子进程注入代理通信配置。

## 简介

本模块在系统中负责管理与云端网络间的隧道通信代理。通过建立基于网络套接字（WebSocket）的本地中继并在环境变量层面注入代理配置与例外策略，它允许大模型执行的子进程透明地穿越内网限制。本模块服务于底层子进程环境，是连接本地沙盒与外部网络的安全基础设施。

## 目录结构

```text
upstreamproxy/
├── relay.ts          # 代理服务器逻辑，负责建立 HTTP CONNECT 到 WebSocket 的隧道及数据帧的手写编解码
└── upstreamproxy.ts  # 环境与鉴权管控入口，负责拉取 CA 证书、实施内存保护并向子进程暴露网络配置变量
```

## 实现逻辑

### 代理初始化与环境隔离

以 `initUpstreamProxy` 函数为初始化入口，模块读取本地会话凭证文件并下载上游的根证书进行合并注入。机制执行中利用外部函数接口（FFI）调用系统底层的 `prctl` 禁止进程核心转储（Core Dump），防止内存诊断工具抓取堆内存中的敏感连接凭证。代理配置计算完成后，通过 `getUpstreamProxyEnv` 以环境变量（如 `HTTPS_PROXY` 及硬编码的 `NO_PROXY` 列表）形式透传给子进程。整个初始化与配置过程严格实施安全失败（Fail-open）策略，任何外部调用异常均会静默处理并退化为无代理直连模式，确保不阻断主进程与子进程的核心运行逻辑。

### 隧道通信与协议截获

以 `startUpstreamProxyRelay` 函数为隧道中继起点，系统伪装为本地通信端口监听流量，拦截来自底层工具的 `HTTP CONNECT` 请求。截获请求后，通过附加凭证发起协议升级握手（Protocol Upgrade），将连接转换为具备权限验证的 WebSocket 隧道。为了消除第三方序列化库带来的巨大依赖开销，数据帧的打包与拆包过程直接在代码中通过人工推演计算二进制偏移量，将数据流封装为精简的协议缓冲区（Protocol Buffers）消息格式。这一机制有效兼容了底层流的差异，并保障了高吞吐通信性能。

## 新增 / 重构 / 删除向导

### 新增

- 扩充系统免代理网段规则时，在配置文件中补充对应的例外请求地址清单。
- 增加隧道通信层的自定义控制报文时，同步更新本地手写的二进制编码与解码逻辑，并补充相应的网络层测试用例。

### 重构

- 涉及网络拦截或环境变量下发的链路必须维持安全失败（Fail-open）属性，发生异常时强制降级为直连，严禁向外抛出致命错误中断上层逻辑容器。
- 修改网络数据缓冲队列及底层套接字（Socket）监听逻辑时，必须同时满足不同运行时环境对数据流背压（Backpressure）的处理规范。

### 删除

- 下线代理网关机制前，必须清除针对系统底层的外部函数接口安全防御调用。
- 必须清理且不再暴露所有针对衍生子进程环境变量作用域注入的证书指向路径及网络代理地址。
