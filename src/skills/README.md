# src/skills — 技能发现与加载注册体系
> 参见 [README.md](../../README.md)
> 相关模块：[src/utils/frontmatterParser.ts](../utils/frontmatterParser.ts)，用于为本模块提供对 Markdown 头部元数据的解析能力。

## 简介
本模块在系统中负责三种级别（系统级、用户级及工程级）自定义扩展命令（技能）的发现、解析、去重以及实例构造。其核心机制是通过遍历特定层级的目录结构提取外部配置，结合内存注册表管理内置组件，再利用反向注入机制切断跨域模块之间的环状依赖。本模块向上层调度引擎与智能体模型提供规范的命令对象（Command）合集，以支持系统的功能延展。

## 目录结构
```text
├── bundled/                 # 内置命令工具库，存放随主程序直接分发的全量静态能力组件及其注册入口
├── bundledSkills.ts         # 静态资源编排器，管理内置命令的挂载状态并在首次触发时将内嵌文件安全释出到磁盘
├── loadSkillsDir.ts         # 动态路径扫描引擎，执行文件系统遍历、元数据提取并基于物理路径进行去重
├── mcpSkillBuilders.ts      # 依赖反转注入中继器，通过缓存构造函数的引用来化解静态打包环境下的模块循环调用问题
└── mcpSkills.ts             # 远端协议代理存根，提供对符合上下文协议规范（MCP）的远程扩展调用的异步拉取接口
```

## 实现逻辑

### 1. 动态技能文件挂载与去重机制
入口点位于 `loadSkillsDir.ts` 中的 `getSkillDirCommands` 导出函数。该机制在系统初始化时，并行扫描内置安全目录、用户配置目录以及工程专属挂载点。为防止跨目录的同源符号链接（Symlink）造成注册对象膨胀，程序利用文件系统的真实物理路径获取接口（`realpath`）生成唯一标识。这种基于文件实体关联（File Identity）的过滤去重策略，保障了单一配置源在多重挂载模式下的唯一实例约束。

### 2. 静态内置资产的延迟释放策略
入口点位于 `bundledSkills.ts` 中的 `registerBundledSkill` 函数。静态配置会在进程启动时全量注入内存队列，通过闭包缓存实现提取契约。当带有附属资源的组件首次被调用执行时，程序利用带有 `O_EXCL` 和 `O_NOFOLLOW` 标志位的安全原子写入指令，将其内联文本释出至当前进程加盐隔离的特定运行时存储区。此种安全失败（Fail-safe）设计有效防范了并发竞态条件（Race Condition）与符号链接劫持攻击。

### 3. 基于依赖反转的模块解耦设计
入口点位于 `mcpSkillBuilders.ts`。由于打包器（Bundler）在处理闭环直接引用时易导致运行时解析崩溃，系统规避了容易受运行期上下文污染的动态指令加载方案，转而由本文件提供纯类型的注册与读取操作闭环。系统启动极早期会主动调用 `registerMCPSkillBuilders` 写入基础构造函数的内存句柄，后续远程通讯代理即可无阻碍地进行读取调用。此机制切断了上下游核心服务直接互相导入的操作路径，维系了全量静态分析的强类型校验边界。

## 新增 / 重构 / 删除向导

### 新增
引入系统内置基础特性时，请在 `bundled/` 目录中编写具体功能逻辑，利用 `registerBundledSkill` 封装技能定义，同时必须在 `bundled/index.ts` 的初始化工厂中同步挂载。增加外部配置扫描来源时，请于 `loadSkillsDir.ts` 补充绝对路径的扫描策略，并且必须为新增策略提供强制的文件访问权校验过程。

### 重构
调整头部元数据（Frontmatter）的解析结构时，必须补充相匹配的类型定义并编写向后兼容逻辑处理。若要改动内置文件的落盘释出操作代码，必须继承并且严格维持对存储目录权限范围的显式限定，始终保有原有设计中的反跨权路径穿越（Path Traversal）防御与安全失败校验。

### 删除
下线动态扩展特性或内置工具时，请在移除对应逻辑构建器之后，务必全面清理 `bundled/index.ts` 以及系统全局引用位置的所有残留注册项，并必须追溯屏蔽所有试图调用该废弃模块的上游组件。移除旧版本配置文件兼容逻辑时，请增加显式的终端错误提示日志，以指引所有下游调用方迁移至全新配置架构。
