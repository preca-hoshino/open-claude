# src/query — 请求查询与执行生命周期模块

> 项目总览：参见 [README.md](../../README.md)
> 
> 相关模块：[`src/coordinator/`](../coordinator/README.md)（协同调度）及 [`src/backends/`](../server/README.md)（底层服务）

## 简介

本模块负责管理单次大语言模型请求（Query）的核心执行生命周期和资源约束。它不仅封装了与模型交互过程中的状态转换（如：请求准备 -> 执行中 -> 等待工具回调 -> 完成），还管理了由于成本和安全限制而引入的 Token 预算和拦截挂钩（Stop Hooks）。

## 目录结构

```text
query/
├── __test__/                        # 生命周期管控相关的单元测试
├── config.ts                        # 单词查询的基础配置参数
├── deps.ts                          # 依赖注入，将外部工具链和执行环境注入当前 Query 上下文
├── stopHooks.ts                     # 终止拦截器（例如：匹配到敏感词或达到强制退出条件时阻断输出）
├── tokenBudget.ts                   # Token 预算与流控器，防止单次会话意外消耗过多额度
└── transitions.ts                   # 状态机，维护 Query 状态转换的安全逻辑
```

## 实现逻辑

### 预算与限流控制
`tokenBudget.ts` 是此模块的防线。它会在每次生成时动态累积并校验已使用的 Token 量，如果逼近用户设定的软上限或平台的硬上限，它会触发预警事件，或者直接通过注入 `stopHooks.ts` 强制终止流式响应，避免造成资源浪费或无限循环（常见于 Agent 自言自语死循环）。

### 状态隔离与转换
由于终端应用中可能并存多个会话或嵌套任务，`transitions.ts` 提供了一个强类型的状态流转引擎。它确保一个正在等待本地 Bash 执行结果的 Query 不会被意外覆盖为“已完成”，从而保持了请求生命周期的一致性。

## 新增 / 重构 / 删除向导

### 新增
- 如果希望增加诸如“流式输出速度监控”、“敏感信息红线拦截”等新阶段特性，应优先以 Hook 的形式插入到 `stopHooks.ts` 中。
- 新增涉及计费、限制和预算的逻辑，需统一在 `tokenBudget.ts` 增加配置项，并补充相关的测试用例保障边界控制准确无误。

### 重构
- 任何针对 `transitions.ts` 状态机的修改极度危险。由于许多上层 UI 组件依赖这里的状态发出重渲染，变更可能导致“死锁”（如进度条永远转圈）。必须伴随详尽的状态枚举测试进行验证。

### 删除
- 如果要废除某些过时的限流逻辑，可移除相应的拦截 Hook 并从 `deps.ts` 依赖树中摘除，同时需保证上层调用方的平滑过渡。
