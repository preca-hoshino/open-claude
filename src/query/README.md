# src/query — 请求查询与执行生命周期模块

> 项目总览：参见 [README.md](../../README.md)
> 
> 相关模块：[`src/coordinator/`](../coordinator/README.md)（协同调度）及 [`src/backends/`](../server/README.md)（底层服务）

## 简介

本模块负责管理单次大语言模型请求（Query）的核心执行生命周期和资源约束。它不仅封装了与模型交互过程中的状态转换（如：请求准备 -> 执行中 -> 等待工具回调 -> 完成），还管理了由于成本和安全限制而引入的 Token 预算跟踪（Token Budget）和流式阻断挂钩（Stop Hooks）。

## 目录结构

```text
query/
├── __test__/                        # 生命周期管控相关的单元测试
├── config.ts                        # 单词查询的基础配置参数
├── deps.ts                          # 依赖注入，将外部工具链和执行环境注入当前 Query 上下文
├── stopHooks.ts                     # 终止拦截器（例如：匹配到强制退出条件时阻断输出）
├── tokenBudget.ts                   # Token 预算与流控器，防止单次会话意外消耗过多额度
└── transitions.ts                   # 状态机，维护 Query 状态转换的安全逻辑
```

## 实现逻辑细节

### 1. Token 预算追踪与边际收益熔断 (Token Budget Tracker)
为了防止大模型在复杂任务中陷入“自我对话”的死循环而消耗天量 Token，`tokenBudget.ts` 设计了精密的熔断机制。
- **软限制续流**：系统追踪每个周期的 Token 增量，在逼近预算阈值（例如 90% 的 `COMPLETION_THRESHOLD`）前，可以不断发放 `ContinueDecision`，并可附带一条 Nudge Message 提示模型控制篇幅。
- **边际收益判定**：当模型已经连续续写超过 3 次，且最近生成的 Token 数量大幅下降（低于 `DIMINISHING_THRESHOLD`）时，系统会判定任务已陷入停滞。此时强制触发 `StopDecision`，掐断模型输出并交还控制权给用户。

### 2. 状态机的一致性与乱序保护 (Transitions)
由于一个 Query 生命周期中，网络 I/O 与本地 Shell 执行是交替进行的异步操作，`transitions.ts` 扮演了严格的红绿灯角色。它能够防止无效的并发状态翻转（例如：在模型还在生成内容时，本地突然弹出一个陈旧的 HTTP 错误并试图把 Query 标记为 Failed）。这种强类型的状态隔障保证了所有上层的 UI (如 Progress Spinner) 不会因为底层时序乱序而卡死。

### 3. 流式分析与强行拦截 (Stop Hooks)
在 `stopHooks.ts` 中挂载了多个底层的文本流分析器。它们不是在获得完整响应后才工作，而是逐字块（Chunk）地嗅探。一旦匹配到诸如安全风控红线，或者是模型意图输出某种不被当前前端支持的伪指令，对应的拦截钩子会直接拉起信号量抛弃后续流，并强行跳转到 `transitions.ts` 的中断态。

## 新增 / 重构 / 删除向导

### 新增
- 如果希望增加诸如“流式输出速度监控”、“敏感信息红线拦截”等新阶段特性，应优先以 Hook 的形式插入到 `stopHooks.ts` 中。
- 新增涉及计费、限制和预算的逻辑，需统一在 `tokenBudget.ts` 增加配置项和策略阈值，并补充相关的测试用例以保障其触发条件符合预期。

### 重构
- 任何针对 `transitions.ts` 状态机的修改极度危险！由于许多上层 UI 状态衍生于此，随意的变更可能导致“死锁”（如进度条永远转圈）。必须伴随详尽的状态穷举测试进行验证。

### 删除
- 如果要废除某些过时的限流逻辑，可移除相应的拦截 Hook 并从 `deps.ts` 依赖树中摘除，同时需保证不打破现有的接口调用契约。
