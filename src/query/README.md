# src/query — 请求查询与执行生命周期模块

> 项目总览：参见 [README.md](../../README.md)
> 
> 相关模块：[`src/coordinator/`](../coordinator/README.md)（协同调度）及 [`src/server/backends/`](../server/README.md)（底层执行模型节点）

## 简介

本模块专注于单次大语言模型请求（Query）的核心计算生命周期及资源边界管理。它负责封装并维护模型交互过程中的确定性状态自动机（例如：初始化准备、流式拉取、工具回调等待、执行终态等）。此外，该架构引入了资源审计层，通过实施精确的 Token 配额预算跟踪（Token Budget）以及基于模式匹配的流式阻断挂钩（Stop Hooks），确保模型推断的安全性与资源利用效率。

## 目录结构

```text
query/
├── __test__/                        # 状态转换协议及生命周期拦截机制的单元测试
├── config.ts                        # 定义单次推断实例的基础配置参数骨架
├── deps.ts                          # 依赖反转容器（IoC），负责将外部环境抽象层挂载至查询上下文
├── stopHooks.ts                     # 输出流拦截器栈（依据正则或 AST 匹配强制熔断当前流）
├── tokenBudget.ts                   # Token 分配流控策略控制器，抑制无限循环反馈
└── transitions.ts                   # 查询状态机实体，维护核心图谱中节点状态转换的原子性与时序安全
```

## 实现逻辑分析

### 1. Token 预算流控与边际效益熔断 (Token Budget Tracker)
为规避模型在处理开放式指令集时，因陷入异常反馈环（Feedback Loop）导致的无节制算力消耗，`tokenBudget.ts` 设计了多级熔断机制。
- **动态延期续算**：系统高频度追踪每个运行周期的 Token 消耗增量。在触及硬性配置限额（如阈值参数 `COMPLETION_THRESHOLD` 设置为 90%）前，控制器将抛出 `ContinueDecision` 事件延续执行，并允许挂载引导信令（Nudge Message）以动态限制大模型端侧生成的冗长程度。
- **边际收益判定**：当观测到模型在连续的多轮续算（通常 $>3$ 轮）中生成的有效 Token 数持续低于临界基准（`DIMINISHING_THRESHOLD`）时，分析器将判定任务图谱陷入收敛停滞状态。系统此时会主动注入强中断事件（`StopDecision`），掐断下游推断流并将系统控制流安全交还至主调用线程。

### 2. 状态机时序一致性与乱序保护 (Transitions)
单次 Query 的生命周期深度交织了网络套接字异步 I/O 与本地系统 Shell 并发调用。为解决这类并发时序问题，`transitions.ts` 扮演了严格的并发时序守卫角色。它从拓扑结构上防止了非法的状态翻转：例如，在推断引擎仍在生成正向反馈时，由于网络延迟导致的旧版本 HTTP 异常（Stale Error）被触发，该状态机将拒绝异常事件覆盖当前进行中的状态。这种强校验隔障确保了上层交互界面层（如 Progress Spinner）不会因底层事件竞态条件（Race Condition）而陷入死锁（Deadlock）式的永久性阻塞渲染。

### 3. 流媒体深度包检测与强制拦截 (Stop Hooks)
`stopHooks.ts` 模块装载了一组位于网络缓冲底层的流媒体分析探针。探针不同于传统的全量解析回调，它们直接对数据缓冲队列执行逐块（Chunk）并发扫描。一旦扫描特征命中如系统安全规范红线，或捕获到当前终端不支持的特殊命令字，钩子驱动器将立即触发底层异常信号源，实施直接阻断，强制切断后续网络包接收，并将关联的流转图快速导向 `transitions.ts` 中的中断终态（Aborted State）。

## 维护规范

### 新增规则
- 新增流处理分析（如实时输出速率监测、敏感关键词审计体系），必须以无状态钩子的形式插拔至 `stopHooks.ts` 管线中。
- 若引入新的计费模型或并发配额限制，需收敛至 `tokenBudget.ts`，并强制补充对应的极限阈值穿透测试用例以验证熔断逻辑可靠性。

### 重构规则
- 对于 `transitions.ts` 内部状态有向图的重构属高危核心变更。任意节点的增删必须充分兼顾上层订阅该状态树的 UI 组件生命周期。提交前必须附带经过严格覆盖率校验的状态路径穷举测试。

### 废弃规则
- 清除历史限流逻辑或拦截探测规则时，应从 `deps.ts` 的注入树及 `stopHooks.ts` 的挂载序列中彻底剥离，且操作必须保证向上不破坏当前组件对外暴露的抽象接口协定（Contract）。
