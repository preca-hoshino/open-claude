# src/constants — 常量与全局配置模块

> 参见 [README.md](../../README.md)
> 本模块由整个项目的所有顶层与底层业务逻辑模块调用，为其提供运行时环境所必须的不可变参数与统一字典。

## 简介

本模块集中维护了系统运行所需的不可变静态参数、默认约束值与文本字典。通过将散落的魔法字符串与硬编码数字统一收敛于各独立领域的模块文件中，保障跨业务链路引用的一致性。本模块作为最底层的纯数据承载层，服务于整个应用代码库的基础调用。

## 实现逻辑

### 1. 按领域拆分的静态配置

入口锚点：`apiLimits.ts` 及各领域文件

机制描述：通过将常量分散至独立的按业务领域划分的文件中，隔离变更影响范围，避免单个庞大配置文件带来的代码冲突与加载开销。每个领域文件充当独立上下文，为整个应用提供确定性的状态值。

关键技术术语：命名空间（Namespace）。

关键约束：文件中仅允许包含纯静态导出声明（`export const`），严禁在此引入任何状态变量及包含副作用的业务逻辑。

### 2. 提示词与动态配置组装缓存

入口锚点：`prompts.ts`

机制描述：采用预定义静态文本块与动态信息获取函数结合的方式构建发送给大语言模型的系统提示词。机制内部通过在固定文本流中预置专门的边界标识符，将可全局缓存的通用静态文本与随着用户会话或本地运行时环境改变的动态文本相隔离。

关键技术术语：缓存边界（Cache Boundary）。

关键约束：在此文件中修改系统提示词顺序时，必须严格维护静态标识符与动态插值段的先后顺序。严禁越过边界调整内容，以免使提示词缓存失效或触发多余的数据重传开销。

## 新增 / 重构 / 删除向导

### 新增

- 扩充系统常量时，精准归入其对应领域的类型文件中，严禁创建无意义的杂项分类文件。
- 必须为附带复杂技术术语的常量在代码上方的文档注释（JSDoc）中提供英文标注与参考用例，保障调用方充分理解配置意图。
- 注册新的系统常量后，必须同时在需要引用该配置的上游模块测试用例中验证其边界取值。

### 重构

- 严禁擅自修改已用于持久化存储、配置文件写入或网络通信传输的枚举值，以防止造成历史数据读取崩溃或兼容性断裂。
- 重构引用关系及命名规范时，必须使用项目全局搜索彻底排查并替换所有下游调用方的接口引用。
- 修改存在安全失败（Fail-safe）或异常降级机制所依赖的默认极限值常量时，必须同时评估并在本模块补充保留安全阈值的备选枚举，避免触发边界条件时引发系统级别的严重错误。

### 删除

- 在确认废弃任何已定义的旧常量前，必须通过全局文本检索确保无任何上游模块的主逻辑、辅助功能及测试用例仍在使用该字段。
- 必须彻底剔除常量声明代码及其对应的所有解释注释和类型限制说明。
- 执行删除操作后，必须要求所有曾使用该常量的上游调用方屏蔽对应的代码分支。
