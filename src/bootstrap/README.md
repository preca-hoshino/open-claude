# src/bootstrap — 全局状态容器与启动隔离模块
> 参见 [README.md](../../README.md)
> 相关模块：`src/utils`（核心工具集重度依赖本模块获取全局运行时上下文与状态配置）

## 简介
本模块在系统中作为全局状态容器，负责集中存储应用程序运行时的全生命周期核心状态。本模块依靠闭包隔离与导出纯函数访问器的方式阻断了底层逻辑代码间的交叉引用，避免了循环依赖。本模块服务于整个系统的各个上层业务节点与工具层，为应用框架提供统一、安全的数据集散中心。

## 目录结构

.

## 实现逻辑分析

### 1. 全局状态隔离与封装
本模块的根基在于 `state.ts` 中定义的 `State` 对象结构。该结构容纳了多达数十项系统数据（涵盖耗时计量、凭据上下文、工作空间路径）。运行时状态经由 `getInitialState()` 实例化后，挂载至未导出的 `STATE` 常量上。这种单例模式（Singleton Pattern）借助闭包隐藏了对象的原始引用，从根本上杜绝了跨模块直接覆写内存配置的风险。

### 2. 状态原子访问限制
本模块不提供字典聚合访问方式，而是强制规定各项状态必须经由一对独立的读取与写入函数操作（例如 `getSessionId()` 用于获取会话，`setChromeFlagOverride()` 用于控制特性）。该设计确立了清晰的控制流骨架，所有调用方的来源及写入目的皆在函数入库层面变得可静态追踪。

### 3. 边界管控与事件协同
为处理涉及复杂生命周期的底层变量切换（如 `switchSession` 或者 `regenerateSessionId` 改变应用级核心 ID），本模块内部嵌入了状态变更广播机制。利用导入的 `createSignal` 函数建立了 `sessionSwitched` 广播通道并对外暴露 `onSessionSwitch` 订阅挂载点，保障上层调用方能够在隔离环境里安全获取会话边界刷新的即时通知。

## 新增 / 重构 / 删除向导

### 新增
追加新状态字段时，请同步在 `State` 类型定义及 `getInitialState()` 的默认返回值中录入初值，随后在同文件底部暴露对应的访问控制器；若字段涉及不同测试用例间的强隔离性，请确保在 `resetStateForTests()` 内补全清理重置逻辑。

### 重构
调整既有字段的提取逻辑时，严禁向本模块引入额外的业务模块依赖引发循环引用；若需调整 `resetStateForTests` 内部逻辑，必须保留其检查非测试环境即刻抛出异常的安全失败（Fail-safe）策略，该策略的安全意图是避免线上生产环境被误调清空数据。

### 删除
淘汰废弃状态时，务必首先全局搜索代码库，彻底追溯并清理全部外部调用方对相应访问器的使用接口；完成上层隔离之后，请将本文件中关联的读写访问器函数、`State` 的内部类型属性声明及初始化代码一并清除。
