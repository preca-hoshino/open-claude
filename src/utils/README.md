# src/utils — 核心通用工具与底层抽象层

> 参见 [README.md](../../README.md)
> 由于本模块作为通用基础设施，被 `src/screens`、`src/services` 与 `src/cli` 以及全量上层业务模块广泛引用。

## 简介

本模块在系统中提供跨业务边界的通用纯函数、环境适配器与底层系统级操作封装。实现这些职责依赖于对底层原生 API 的包裹（如文件系统与子进程）、对标准数据结构的扩展以及对第三方协议（如 Git 与 MCP）的基础实现。本模块作为整个项目的最底层基础设施层，服务于所有的上层业务逻辑。

## 实现逻辑

### 1. 系统与环境适配器

通过 `env.ts`、`process.ts` 与 `platform.ts` 作为入口，封装系统底层原生 API，屏蔽不同操作系统之间的底层差异。此机制通过统一的跨平台抽象层，确保上层业务无需处理路径分隔符、进程信号、终端特性或特定平台问题。

### 2. 网络与协议封装

本模块包含对 HTTP 以及相关网络传输规范的底层封装。通过在特定工具函数内内置重试策略、超时断开与错误分类机制，提供可靠的网络通信通道（Communication Channel），确保全链路监控埋点的标准化与稳定投递。部分模块包含安全失败策略，即使网络出现故障也会静默降级处理。

### 3. 数据与文件处理

由 `fsOperations.ts`、`json.ts` 与 `markdown.ts` 组成主干。主要提供了面向大规模数据或复杂格式（如 Markdown 前言、特定 JSON Schema）的高效序列化/反序列化与 IO 读取，通过增加缓存层和流式处理以降低内存占用（Memory Footprint）并提升读写效率。

## 新增 / 重构 / 删除向导

### 新增

请评估新增工具函数的跨模块复用价值；若仅为单一模块服务，请将其移至对应的上层业务模块内部；添加新工具类时必须包含完整的导出接口注释，并在相应测试目录中补充针对边界条件的自动化测试用例。

### 重构

修改现有工具函数时务必保持严格的向后兼容性（Backward Compatibility）；若必须变更函数签名或异常抛出类型，请全量检索并重构系统中的所有调用方；针对处理凭证类敏感数据的部分模块由于其内建安全失败（Fail-safe）策略，重构时必须显式保证此类安全异常不会被错误捕获从而导致故障敞口（Fail-open）。

### 删除

仅当工具函数无任何上游依赖时方可进行清理；下线前请执行全局静态分析与代码搜索，追溯并移除所有的隐式引用，同时务必连带清理关联的测试用例与类型声明文件。
