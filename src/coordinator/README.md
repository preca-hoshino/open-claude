# src/coordinator — 代理协调与并行调度模块

> 项目总览：参见 [README.md](../../README.md)
> 
> 相关模块：[`src/remote/`](../remote/README.md)（可能有远程通信涉及）或 [`src/query/`](../query/README.md)（协同查询）

## 简介

本模块用于支持高级的多代理协同（Multi-Agent Coordination）或分布式任务拆解执行架构。当系统面对复杂请求时，协调器能够将任务分配给不同的后台 Worker Agent 进行并行或流水线式处理，最后再将结果进行汇总整合。

## 目录结构

```text
coordinator/
├── __test__/                        # 协调器状态机与子代理通信逻辑的测试
├── coordinatorMode.ts               # 主协调器模式的控制逻辑，负责派发与汇总
└── workerAgent.ts                   # 工作代理（子 Agent）的抽象与状态追踪
```

## 实现逻辑

### 主从模式调度
`coordinatorMode.ts` 定义了任务拆分与合并的生命周期。它根据上游指令构建一个“主（Coordinator）— 从（Worker）”的代理拓扑结构。在这个模式下，主代理不会直接执行如文件读写等具体工具调用，而是将大块任务划分为子计划派发。

### 独立上下文处理
`workerAgent.ts` 表示被派发出去的独立工作单元。为了防止不同子任务之间的上下文污染，每个 Worker Agent 在隔离的环境（可能包含独立的消息堆栈、Token 配额）中运作，并在完成分配的工作后将结构化结果上报给协调器。

## 新增 / 重构 / 删除向导

### 新增
- 若希望加入新的并行任务拓扑（如“竞速模式”：多个 Worker 同时尝试解答，取最快且成功的），请在此扩展调度逻辑。
- 必须在 `__test__` 中增加极端的并发条件和异常捕获用例，例如验证某个 Worker Agent 崩溃时协调器能否正确重试或降级。

### 重构
- 如果底层网络结构或消息通道（例如从单机内存通道变为基于 WebSocket 的跨机器通道）发生改变，需要重点重构 Worker Agent 的状态追踪协议。

### 删除
- 如果项目改变产品方向，决定废除复杂的多 Agent 架构而回归单体串行 Agent，则可安全废弃本模块并清理入口处有关 Coordinator 模式的启动分支。
