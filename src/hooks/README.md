# src/hooks — React 钩子与全局状态桥接模块
> 参见 [README.md](../../README.md)
> 相关模块：`src/state`（提供 AppState 供 Hook 消费与修改），`src/bridge`（提供 REPL 到服务端通信的基础接口，本模块负责状态映射）。

## 简介
本模块负责通过 React Hooks 封装和连接底层核心逻辑与前端组件的生命周期。核心机制是基于 `useEffect` 和全局状态订阅，将应用状态、通知、工具权限管控、终端尺寸监控以及外部通信转化为驱动 UI 渲染的响应式状态。本模块服务于上层 UI 视图层（包含终端 Ink 组件），确保界面能在状态或底层事件变更时实时且安全地更新。

## 实现逻辑

### 1. 状态桥接与副作用隔离
入口：`useXxx.ts` 系列文件（以 `useIDEConnectionStatus` 为例）
本模块依赖 React 的 `useEffect` 和全局状态仓库进行底层事件订阅。机制描述：Hooks 在挂载时注册底层事件监听（包括连接状态改变、消息队列变更），并在状态更新时触发内部状态（State）变更。这避免了组件直接操作底层实例，保障了前端 UI 和业务核心引擎的解耦（Decoupling）。

### 2. 工具权限管控体系
入口：`useCanUseTool.tsx`
本模块负责处理工具执行前的最终授权判定。机制描述：首先结合全局配置与分类器（Classifier）尝试无感放行或直接拒绝；若判定结果不明确，则挂起执行转入交互流程，通过系统弹窗或终端交互请求用户许可。同时，通过调用 `toolPermission/PermissionContext.ts` 记录用户的权限决策历史（永久批准或单次允许），防止同一工作流中的重复打断。关键约束：所有权限校验异常均抛出并在最外层捕获后终止执行，确保无授权时不发生越权操作。

### 3. 长链接与外部会话管理
入口：`useReplBridge.tsx` 和 `useVoiceIntegration.tsx`
本模块负责维系跨越多次命令交互的长生命周期通信（Long-lived Connection）。机制描述：REPL 桥接会在底层网络重连、认证状态变更或心跳超时发生时，自动清理旧句柄并重新初始化长连接，同时将远端消息转化为本地终端显示格式。上述机制内置了安全失败（Fail-safe）策略：当重试连续失败超过设定阈值后，将停止重试并自动禁用该桥接功能，防止陷入死循环或耗尽网络资源。

## 新增 / 重构 / 删除向导

### 新增
请将新功能相关的逻辑抽离为独立的 Hook 并放置在与其职责匹配的对应目录。务必在 `useEffect` 的返回函数中显式提供副作用的清理（Cleanup）操作；完成开发后，请补充对应的挂载与卸载的自动化测试用例，并在使用此 Hook 的组件内注册入口。

### 重构
修改现有 Hook 的入参签名或底层依赖时，请保持向后兼容性或全量更新所有相关调用方。本模块内（特别是 `useCanUseTool.tsx` 与 `toolPermission` 目录）涉及的安全失败（Fail-safe）策略和故障敞口（Fail-open）判定必须严格予以保留，禁止更改权限拦截的异常默认拒绝行为（Deny by default），以防恶意代码越权。

### 删除
确认该 Hook 的业务逻辑完全下线后，直接移除该文件。请全局搜索并移除所有上游调用方对该入口的引入；清理过程中，须确保剥离相关全局状态变量（包括 AppState 中专为该 Hook 保留的字段），彻底切断所有的关联逻辑。
