# src/components — 终端用户界面与交互控制层

> 参见 [README.md](../../README.md)
> 关联模块：[src/state](../state/)（提供组件挂载所需的全局状态机与交互上下文），[src/ink](../ink/)（提供底层终端渲染引擎封装与自定义渲染钩子）。

## 简介

本模块负责构建交互式命令行应用（CLI）的全景用户界面。主要结合 React 框架与底层终端引擎驱动节点树的流式输出，并针对高频消息变更实施了细粒度状态管理与防抖机制。作为直接承接终端用户的系统展现层，本模块动态可视化所有前端事件、代理模型回执以及底层系统反馈。

## 目录结构

```text
src/components/
├── App.tsx # 顶层应用外壳，注入全局状态与性能分析数据收集器
├── FullscreenLayout.tsx # 全屏模式布局引擎，支持虚拟滚动控制、多层悬浮弹窗与可视区图层隔离
├── Message.tsx # 多态消息分发路由器，依据数据结构类型执行节点树的条件装载
├── Messages.tsx # 历史消息队列容器，管理上下文字母堆叠与边界界定计算
├── VirtualMessageList.tsx # 虚拟化消息长列表，为海量会话内容提供按需挂载与视口保护
├── ui/ # 通用基础视图库，涵盖布局容器、输入提示组件与可复用无状态文本块
├── messages/ # 领域专属富文本组件片段，解析具体的后端应用响应与日志实体
├── mcp/ # 模型上下文协议关联交互视图与协议配置向导
├── permissions/ # 系统沙盒安全卡点视图，渲染权限拦截提示与用户操作校验面板
└── ... # 其他基于 React 构建的子业务弹窗、提示微控件以及垂直功能抽屉
```

## 实现逻辑分析

### 1. 顶层挂载与上下文隔离
挂载入口为 `App.tsx`，在组件树顶端提供了 `AppStateProvider` 以及 `FpsMetricsProvider` 全局状态分发器。该架构模式将高频的后台状态突变以及性能采样数据限制在顶层，配合深层子节点的细粒度状态订阅（采用 `useSyncExternalStore` 机制）来消除全量级重绘。此举能够在海量并发日志输出期间，稳定终端应用界面的刷新帧率。

### 2. 终端全屏布局架构
全屏图层控制中心位于 `FullscreenLayout.tsx`。为突破纯命令行的线性输出局限，本模块引入了独立的滚动容器并确立了三维图层空间锚点。配合上下文体系，界面能够将输入联想与配置侧栏精确渲染在主内容区之上而不互相破坏排版。内联计算钩子 `useUnseenDivider` 则独立跟踪用户滚动偏移量，实时计算并显示未读计数挂件。

### 3. 多态消息解析与分发
负责处理最密集的聊天记录区域的是 `Message.tsx` 组件。底层传入的各类结构化数据依据分支逻辑进行强类型分发拦截。由于节点极为冗长，模块广泛部署了记忆化拦截逻辑（Memoization），采用严格的属性等价性比对机制。仅当子结构特定控制符（例如 `lastThinkingBlockId` 或指令执行状态）发生偏移时，触发节点刷新，从而杜绝由流式流出引发的树状连带刷新。

## 新增 / 重构 / 删除向导

### 新增
新增终端用户界面组件时，遵循现有的声明式渲染规范并将其归类至指定子目录内；若需要引入全新的流式消息交互，在 `Message.tsx` 交换机中注册路由，并在 `messages/` 目录下建立解耦的展示容器，同时必须为该容器编写完备的属性强类型声明与兼容性降级策略。

### 重构
若调整波及核心布局流或虚拟列表（如修改 `FullscreenLayout.tsx` 的视口尺寸测算逻辑），严格且穷尽地测试全向兼容性，尤其是页面滚动状态的回看保留（Scrollback）；本模块内部深度挂载了针对不可控宿主终端的异常隔离策略（Fail-safe），在剥离或重建底层上下文环境时，务必保留并验证备用降级管线，确保渲染失败时终端进程不发生致命级挂起。

### 删除
汰换过期视图组件或输入对话框时，强制同步清查并抹除 `src/state` 中关联的业务控制参数与调用源；精准追溯该组件在所有父级作用域中的挂载点并执行物理断开；完成代码剪除后，手动开展终端不同分辨率缩放测试，核实被删除目标原本占据的视图矩阵不会诱发弹性盒模型（Flex Box）出现塌陷或发生不可逆的内容隐藏。
