## 简介

Proactive 模块负责驱动系统的主动行为。它包含在特定触发条件下或后台静默运行时主动发起的任务与状态变更逻辑，提升助手的智能化程度与用户体验。

## 目录结构

```text
proactive/
├── index.ts                         # 模块统一导出入口
└── __test__/                        # 测试目录
    └── ...
```

## 实现逻辑

### 行为触发器
通过监听系统事件、文件变动或后台定时器，本模块实现了一套响应式的主动触发机制。系统可以在无需用户显式输入指令的情况下主动推送建议或发起操作。

### 会话状态介入
主动发起的逻辑会通过特定接口介入到现有的 assistant 会话流中，模拟系统或代理的异步返回，确保用户界面能够正确接收并渲染这些主动推送的消息。

## 新增 / 重构 / 删除向导

### 新增
- 添加新类型的主动行为前，需确立该行为的触发条件边界。
- 必须编写对应的 `__test__` 测试用例，防止意外的全局死循环调用。

### 重构
- 如果重构底层的事件监听或定时调度机制，需保证原有的异步上下文不会因重构而丢失。
- 确保主动消息插入会话时不破坏正常的对话序列号和锁定状态。

### 删除
- 在移除某种主动行为时，除了删除相关逻辑文件外，还需要解绑与之对应的监听器（EventListener），防止内存泄漏。
