## 简介

Daemon 模块负责应用的长期驻留进程。该模块主要承载应用的后台 Worker 注册表和守护逻辑，以确保核心后台服务的持久运行与健康状态监控。

## 目录结构

```text
daemon/
├── main.ts                          # 守护进程入口文件
├── workerRegistry.ts                # Worker 注册表，用于管理已启动的后台进程
└── __test__/                        # 测试目录
    └── ...
```

## 实现逻辑

### 进程生命周期托管
`main.ts` 定义了独立于主 UI 的守护进程启动与心跳维持逻辑。它的主要职责是确保应用在后台以稳定和被监控的方式常驻，防止因前台退出而中断关键服务。

### 工作线程注册表管理
`workerRegistry.ts` 实现了状态隔离的 Worker 注册与发现机制。通过中心化的记录台，其他模块可以寻址到活跃的特定工作线程，实现多路复用。

## 新增 / 重构 / 删除向导

### 新增
- 引入新的 Daemon 子服务时，必须在 `workerRegistry.ts` 中完成合规的类型注册，并实现启停接口。
- 新增守护进程功能需考虑跨操作系统的兼容性测试，并在 `__test__` 中覆盖注册流程验证。

### 重构
- 任何针对生命周期或注册表的重构，都需保证向后兼容，防止出现旧版客户端无法发现新版 Daemon 的通信断层。

### 删除
- 清理或停用 Daemon 功能时，请优先实现优雅退出的清理流程，保证已存活的后台任务不被强制杀掉，以免造成状态或数据损坏。
