# src/plugins — 插件与扩展模块

> 项目总览：参见 [README.md](../../README.md)
> 
> 相关模块：无直接强相关模块（作为系统独立的能力扩充载体）

## 简介

本模块构成了项目的插件架构，主要用于存放和管理系统内置（Built-in）及捆绑（Bundled）的插件能力。这些插件使得核心应用在不修改底层架构的前提下，能够以模块化的形式注入特定领域的扩展特性或工具集。

## 目录结构

```text
plugins/
├── __test__/                        # 针对内置插件的自动化测试
├── builtinPlugins.ts                # 内置插件的统一管理、解析与加载逻辑
└── bundled/                         # 存放独立捆绑分发的官方插件库
    ├── index.ts                     # 捆绑插件的暴露与初始化入口
    └── __test__/                    # 捆绑插件套件的关联测试
```

## 实现逻辑

### 插件生命周期管理
`builtinPlugins.ts` 承担了核心的调度角色，它提供了一套统一的接口协议，用于发现、解析和初始化系统中挂载的各个扩展插件。确保每个插件能按需注入到主应用的上下文中，且在系统销毁时正确地进行资源清理。

### 官方生态隔离
为了保证应用核心（Core）的纯净度，将具备独立业务闭环的官方实现抽离至 `bundled/` 目录下。这既方便了统一打包分发，也有利于未来将这些插件抽出为独立的 NPM 包或允许第三方开发者参考其模式实现自定义扩展。

## 新增 / 重构 / 删除向导

### 新增
- 若希望为系统提供一种可独立插拔的新工具或行为（例如某种全新的大模型解析套件或第三方服务连接器），请在 `bundled/` 下新增目录进行开发。
- 新增插件完成后，必须在 `builtinPlugins.ts` 或 `bundled/index.ts` 的入口处显式注册，并编写相应的 `__test__` 测试用例来验证其注册与加载无异常。

### 重构
- 在变更插件的接口规范（如初始化参数或回调机制）时，必须全量扫面 `bundled/` 内的所有既有插件，保证它们对新接口完全兼容。

### 删除
- 如果某个内置插件已过时或被新的内置逻辑取代，可以在 `bundled/` 中将其删除，并切断 `builtinPlugins.ts` 对其的任何显式引用。
