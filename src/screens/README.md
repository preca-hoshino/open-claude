# src/screens — 全屏终端交互界面模块
> 参见 [README.md](../../README.md)
> 本模块的各个屏幕组件主要由 [src/commands](../commands/README.md) 触发，并在界面构建时深度依赖 [src/components](../components/README.md) 提供的基础 UI 组件。

## 简介
本模块负责提供系统中最高层级的全屏终端用户界面（TUI），承载用户的核心交互流程。其依赖 React 和 Ink 库实现基于文本的动态屏幕渲染机制，将底层的会话逻辑、历史记录解析和系统环境检查结果转化为可视化视图。本模块作为前端展现基础设施，直接服务于应用的命令行入口，完成从命令分发到界面接管的最终展现。

## 目录结构
```text
.
├── Doctor.tsx              # 诊断信息屏幕，负责环境探测、依赖检查与告警的统一展现
├── REPL.tsx                # 主交互屏幕，提供核心的读取-求值-输出循环与输入栏、会话流渲染
└── ResumeConversation.tsx  # 会话恢复屏幕，负责查询历史日志、展示会话列表并重构应用状态
```

## 实现逻辑分析

### 1. 诊断界面
以 `Doctor` 组件为入口，集中进行系统级环境探针的调度。界面挂载时，通过 `getDoctorDiagnostic` 异步收集原生依赖状态、环境变量（如 `BASH_MAX_OUTPUT_LENGTH`）、活跃的 MCP 工具和插件错误等信息。其使用 `useState` 与 `useAppState` 分离只读配置与运行时状态，最终通过一组条件渲染逻辑将散乱的检查结果聚合并格式化为列表输出给用户，若无环境异常，则展示安全的通过状态。

### 2. 主交互循环
以 `REPL` 函数为核心，是系统中最为庞大的 UI 骨架组件。内部集成多个独立的机制，如通过内部的 `TranscriptSearchBar` 处理成绩单过滤与搜索、通过 `AnimatedTerminalTitle` 进行终端标签页动态更新。它强依赖 `useAppState` 读取会话相关的状态，并通过 `useEffect` 在应用启动时完成本地状态补齐（如合并磁盘日志与流式输出）。其核心作为会话的容器，接收用户指令并下发至内部封装的 `Messages` 渲染流及输入交互器。

### 3. 会话恢复
由 `ResumeConversation` 函数负责渲染历史会话列表器。该屏幕加载时利用 `loadSameRepoMessageLogsProgressive` 从本地持久化存储异步提取当前工作区的会话日志（`LogOption[]`）。用户确认选择后，其内部会执行复杂的还原逻辑：恢复会话指针、拉取对应的代理定义、以及还原工作区配置（如 `restoreWorktreeForResume`）。该组件最终会返回组装好初始属性的 `<REPL>` 组件，将执行流无缝移交给主交互屏。

## 新增 / 重构 / 删除向导

### 新增
- 新增全屏界面时，需确保组件顶层处理好 `useKeybindings` 快捷键捕获，避免按键事件意外穿透到背景进程。
- 必须通过 `useExitOnCtrlCDWithKeybindings` 或自定义逻辑处理好安全退出机制（如捕获中断信号）。
- 新增组件后，须在入口分发器或对应命令层完成挂载路由的注册。

### 重构
- 任何对状态读取（如 `useAppState`）的重构，必须保证向后兼容旧版日志结构的解析，以免阻断历史会话恢复。
- 若本模块包含界面阻塞（如同步解析巨量日志）故障敞口，须重构为渐进式加载或包含明显的进度提示，以符合体验安全预期；相关安全失败（Fail-safe）策略须在代码中显式保留。
- 修改屏幕布局时，不可破坏现有对于终端尺寸的假设，必须使用 `useTerminalSize` 动态获取可用空间。

### 删除
- 下线某屏组件前，必须清空相关的持久化日志缓存并注销对应的 CLI 命令路由。
- 必须全面追溯并屏蔽所有指向该屏幕组件的上游调用方入口。
- 删除后，确保清理与该屏幕深度绑定的特有状态切片。
